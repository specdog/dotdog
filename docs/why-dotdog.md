## The problem with traditional specs

| Approach | Problem |
|----------|---------|
| Wiki pages | Written once, never updated. No validation. |
| Google Docs | No structure. AI agents cannot query. |
| README files | Prose only. Agents hallucinate from loose descriptions. |
| OpenAPI/Swagger | API-only. No UI, states, flows, predictions. |
| Jira tickets | Task-oriented. Lose the big picture. |

## What dotdog adds

| Feature | How it helps |
|---------|-------------|
| Structured format | Markdown + YAML. Humans and parsers both understand. |
| Validation | Scores completeness. Finds gaps before code is written. |
| Compilation | 94pct token savings. Optimized for LLM context windows. |
| MCP server | AI agents query specs. Zero hallucination. |
| Staleness detection | Compares plan.dog tasks against code. Catches drift. |
| Predictions | Track forecasts and score against reality. |
| Dogfooding | dotdog validates its own specs at 100pct completeness. |
